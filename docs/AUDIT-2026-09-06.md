## Итог и границы проверки

Существенное обновление roadmap необходимо. Главные проблемы — несогласованные источники текущего состояния, невоспроизводимая из root patch MTP-конфигурация, недостаточно строгие границы измерений и преждевременный переход от attribution к сложной asynchronous реализации. Сервер, модель, сборки и benchmark не запускались; отсутствующие raw данные не восстанавливались повторными опытами.

Снимок: root `main`, HEAD `3c02e5de56061c7c30c45ec325a0d8845639c825`. До аудита уже изменены README и `experiments/EXPERIMENTS.md`; EXP-028–033, входной запрос и `agents.md` были untracked. `work/llama.cpp-integration` на upstream `4aaad5d...` содержит многочисленные функциональные изменения, включая MTP, а не только восемь comment edits, как утверждает старый CURRENT_STATE. ## Приоритетные находки

### A1. MTP не воспроизводится из опубликованного patch — высокий приоритет

`patches/expert-tier-integration.patch` содержит safety/hotstore изменения, но не MTP `mtp_only`/`model_shared`/speculative port, находящийся в dirty nested source. `scripts/prepare_upstreams.sh` закрепляет `4aaad5d...`; его `integration_present()` проверяет несколько marker strings и может признать произвольную локальную смесь актуальной. CMakeCache working server указывает integration tree; exp023 build — `work/llama.cpp-exp023`. Один root SHA не идентифицирует эти binaries.

Нужно отдельно упаковать минимальный MTP diff с происхождением и проверить isolated clean reconstruction. Не менять upstream, не копировать целиком сторонний fork, не извлекать пользовательские comment edits в доставляемый patch. Существующий prepare script не запускать для «починки»: он fetch/checkout upstream trees и не доказывает полную эквивалентность исходников.

### A2. Safety заявлена шире фактического launcher — высокий приоритет

`common/common.h` задаёт `swap_watchdog=false`, `tools/server/server.cpp` запускает его условно. Ни default launcher argv, ни показанная в README MTP-команда не содержат `--swap-watchdog`; внешний env override может изменить ситуацию, поэтому утверждение относится к defaults.

В `scripts/run_qwen38_server.sh`: `sys_rate` уже MiB, но hard threshold равен `2097152`, а внутренний watchdog использует `2048`. Burst VmSwap сравнивается правильно с `262144 KiB`, но diagnostic message умножает на 4, завышая MiB. `wait "$RUN_PID"` под `set -e` может выйти до monitor cleanup при ненулевом server exit. Зафиксировать эти дефекты и устранить отдельным safety этапом с синтетическими samples, без генерации настоящего swap.

Launcher также default `CTX_SIZE=8192`, не 64K/32K; не задаёт исторические q4_0 KV/reasoning/MTP flags. «Запусти стандартный launcher» недостаточно для сопоставимого baseline. 8 GiB startup check не резервирует 8 GiB после загрузки; `EHS=0` не включает универсальную VRAM reservation.

### A3. Доказан объём transfers, но не полная причина latency

EXP-031 GPU duration sum 1,661 s и kernel sum 0,439 s нельзя складывать с host API/span, вычитать из wall time и объявлять остаток idle: интервалы могут пересекаться. EXP-032 span 3,635 s — от первой до последней submission, не сумма ожиданий PCIe. 100% относится к измеренной выборке backend expert uploads; Nsight видит ещё другие H2D. В тексте EXP-031 единицы названы 22,2 GiB, но 22160,56 MiB = 21,64 GiB (23,237 GB).

При offline чтении сохранившегося `/tmp/exp031b-cuda-prefill-1788632387.sqlite` найдено 19 218 H2D за всю сессию, включая startup, и 3706,01 ms суммарного host `cudaMemcpyAsync` API за всю сессию. Это проверка наличия данных для корреляции, НЕ новый request benchmark и НЕ замена 17 975 in-request calls. Нужны window alignment, correlationId и union intervals. Новый profiler run разрешён только если конкретный недостающий сигнал невозможно извлечь из сохранённого trace.

### A4. EXP-033 не доказывает, что два whole-projection buffers исправят проблему

Patch добавляет CPU memcpy выбранных ranges, upload во временный device payload, byte scatter и event перед reuse. Регистрировать причину только как event serialization слишком сильно: gather/scatter/pool allocation costs отдельно не измерены. Увеличение числа больших projection buffers может добавить сотни MiB к tight VRAM и не снять межsplit waits. `sched->cur_copy` — индекс scheduler copies, не ring для последовательных projection submissions.

Предлагаемый меньший шаг: bounded host ring прямых range copies, без device payload/scatter и ID remap. Он проверяет собственную гипотезу (pageable submission/host preparation), не гарантирует выигрыш. Same stream сохраняет copy→compute порядок; отдельный stream — отдельный последующий эксперимент. Все allocator barriers остаются до доказательства lifetimes. Router N+1 зависит от результата FFN N; «prefetch next layer» не является готовой реализационной стратегией.

### A5. Correctness gate пока недостаточен для нового async пути

`test_small.sh` относится к bmoe-cli, ubatch=8. Candidate guard EXP-033 был `ne[2]>=32`: существующий smoke может вообще не войти в новый путь. Более того, Perl extraction может дать два пустых файла при изменении output marker, и `cmp` ложно пройдёт. Нужны coverage counters на multi-token scheduler host→CUDA path, nonempty fixture checks, byte сравнение выбранных payload включая MMQ padding, sparse IDs/последний expert, forced slot reuse, fallback, cancellation/teardown. `test-backend-ops` отдельно не доказывает scheduler copy lifetime.

Одинаковый короткий content hash не доказывает полную маршрутизацию или MTP rollback. Разные hashes нельзя автоматически назвать near-tie: в EXP-023/024 это объяснение из журнала без сохранённой margin/logit верификации. Для transfer-only кандидата одинаковые settings должны сохранять tokens/контент; расхождение блокирует приёмку, а не ослабляет gate. Replay forced routes проверяет workload identity, не неизменность router вычислений.

### A6. Качество и обобщаемость чисел

Историческое +13,6% MTP сохраняется, но это один measured pair, не five-run median; EXP-028 JSON содержит четыре warm samples на arm при пяти совпавших ответах (пятый не равен пятому measured warm). EXP-033 decode 19,83 vs 20,85: около −4,9%, короткие 16 tokens не дают надёжной оценки decode regression. Значения 3,0 s (028) и 4,0 s (033) пересекают builds/context/cache state; это не доказательство новой регрессии.

В EXP-024 журнале указано 311 reused graphs, сохранённый MTP server log имеет 104 после первого запроса и 207 после второго (cumulative); 311 похоже на повторное суммирование счётчика. Не использовать эту цифру для арифметики ускорения.

EXP-026 history note указывает 99,9%, журнал — 99,5% внутри main mapping. Арифметика 206114/(85243+124275) = около 98,38%; глобальные 95,07% правильны. Исторические записи не удалять, добавить correction. Fault counts не дают per-expert stall durations и не доказывают полное kernel overlap.

EXP-019 generic PMU cache-misses нельзя без проверки Zen 3 event semantics считать буквально LLC line fills и DRAM bytes. Single-core read-only ceiling не устанавливает потолок 12-thread сервера. Cycle shares вместе со spin не равны долям request wall time. Это ограничивает универсальные выводы «не может дать material win», но не оправдывает повтор уже отклонённых kernels без новой evidence.

### A7. Слишком широкие закрытия/переоткрытия фаз

EXP-027 обоснованно закрывает unsafe warmer, но одна пара и crash correlation не доказывают, что весь P1 или все residency strategies бесполезны. EXP-030–032 исследуют другую фазу, bulk prefill, поэтому её развитие не повтор 012/027. Обратная ошибка README — снова перечислять io_uring/O_DIRECT/router prefetch без привязки к новому critical path. Exact-adjacency H2D coalescing уже реализован, не предлагать его как новый эксперимент.

Неизмеренные graph fusion/barrier reduction, CPU affinity/topology, MTP verification shape-specific kernels, natural long-conversation cache pressure и limited-gap H2D coalescing остаются возможностями, но не входят в активную очередь. Сначала нужна новая измеренная верхняя оценка пользы. Ни низкий GPU utilization, ни закрытие других направлений сами по себе не обосновывают их реализацию.

### A8. Сохранность свидетельств и статусов

История распределена между docs, journal, JSONL, JSON и ignored worktrees. EXP-028–033 не были tracked на момент аудита; ряд raw traces только в `/tmp`, raw SSE/monitor logs ignored; часть ранних решений имеет только текстовый отчёт. `history.jsonl` не полный индекс и содержит последующие retractions: нельзя читать только первую запись EXP. EXP-026 всё ещё начинается с PLANNED, хотя execution выполнен. Новый roadmap является актуальным порядком; старые Next experiment — исторические.

Нужен manifest: artifact path, SHA-256, tracked/local/missing, source/binary/lib identities, argv/env/request, warmup/measured exclusions. Отсутствующий файл = `MISSING`, не повод повторить опыт. Исторический `aggregate_baseline.py` не верифицирует все hardcoded identity/parameter значения и не является серверным harness; `test_small.sh` при отсутствии CUDA завершает skip с кодом 0, что не равно CUDA gate passed.
