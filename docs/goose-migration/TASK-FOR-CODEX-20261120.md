## The chain that was walked tonight, so you do not re-walk it

Each line was a real failure with a real cause; the fixes are in `tools/build-from-tree.sh` and
`tools/consolidate-runtime-tree.sh`.

1. **11 doors** - the composed unit was never linked. Now linked, and the build **refuses** without it.
2. **`R_X86_64_PC32` against `stderr`** - the staged unit is built for an executable; a PIC copy is compiled
   from the same generated C.
3. **duplicate `q35_shape`/`qg_split`/`goose_init`** - extra objects the unit supersedes are skipped by name.
4. **`undefined symbol: llama_goose_register`** - `integration/goose-standalone/gguf-reader-owner.cpp` is now
   in `our-src`.
5. **`undefined symbol: fg950_goose_init`** - the adapter calls the unit's init by `build.py`'s define;
   the PIC compile passes `-Dgoose_init=fg950_goose_init`.
6. **`undefined symbol: goose_init`** - the rest of the tree uses the other name; a one-line shim calls
   through.
7. **`undefined symbol: goose_tok_enabled`** - the C++ m1 bridges were compiled by no consolidated set. They
   are now copied and compiled, and the generated headers they include are produced:
   `config-slice.h`, `metrics-traces.h`, `stream-policy.h`, `slru-policy.h`.
