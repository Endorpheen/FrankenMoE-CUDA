# The standalone runtime already loads the full Apex model. The status said otherwise.

Measured 2026-11-16 by running the shipped artifact on the real file:

```
$ ./builds/goose-standalone/frankenmoe-v4 <Apex-35B-V1.0-Q4_K_M.gguf>

FG_TENSOR_DATA rc=0 tensors=753 total=21702472192 copied=21702472192 layout=0 mismatches=0
           first_size=417177600 last_size=8192 first_byte=92 last_byte=0
FG_STANDALONE_V3 init_runs=1 types=43 kv=52 tensors=753 first_key="general.architecture"
           goose_built=52 goose_first="general.architecture" agree=yes
           tensors_added=753 tdir_n=753 align=32 ne0_sum=1222904

wall=23.12s  maxRSS=21236724 kB
```

**21 702 472 192 bytes = the entire tensor payload of a 21.7 GB model, laid out through the Goose
allocator arithmetic with zero mismatches**, and the Goose metadata module rebuilding the same 52 keys and
agreeing with the container.

## Why this had been invisible

`migration-status.sh` used the v4 binary only to count `tok_*` symbols (line 119). It never ran it on a model,
and the line about model loading was hand-written:

```
model load + graph build   partial (EXP708/713: the integrated stage-run serves Apex
                           32K/end-to-end with output identical to the reference,
                           but that is the integrated tree, not this runtime)
```

The caveat in that line - "that is the integrated tree, not this runtime" - is the part that was right, and
it stopped being the whole story: **this runtime does read the model.** What it does not do is *execute* it.

So the honest split is finer than the status drew:

| capability | this runtime |
|---|---|
| read the GGUF container | yes |
| read all 21.7 GB of tensor payload, laid out by Goose arithmetic | **yes, 0 mismatches** |
| rebuild the metadata key table through Goose and agree with the container | **yes, 52/52** |
| execute the graph, produce logits, serve | no |

## What it does not prove

Reading and laying out a tensor is not running it. No kernel touches these bytes; `mismatches=0` means the
bytes match the file, not that a matmul over them is correct. Rule 15's test is untouched: the export must
answer the capability, and executing the model is the capability, not loading it.

## Cost and how to reproduce

23 s wall, 20.2 GiB peak RSS - the model is held in the arena. That is why it is not part of the default
build check: it is a heavyweight verification that needs a reason to run, not a smoke test.

```
bash tools/build-standalone-runtime.sh          # builds frankenmoe-v4
./builds/goose-standalone/frankenmoe-v4 models/Apex-35B-V1.0-Q4_K_M.gguf
```
