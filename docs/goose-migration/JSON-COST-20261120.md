# The JSON-carrying set answers correctly and costs 3-5% - measured, paired

Four runs on 2026-11-20, same profile, port 9101, one at a time, model 100% resident, minutes apart.

| set | decode (3 runs) | median | prefill (3 runs) | median | VRAM | hash |
|---|---|---|---|---|---|---|
| baseline `run-candidate` | 61.26 / 62.04 / 61.67 | **61.67** | 2656.3 / 2929.7 / 2923.8 | **2923.8** | 9465 MiB | `c2ff42cc1219` |
| baseline + adapter `run-json` | 59.21 / 59.57 / 61.45 | **59.57** | 2538.5 / 2796.5 / 2783.5 | **2783.5** | 9465 MiB | `c2ff42cc1219` |

Delta: **decode -3.4%**, **prefill -4.8%**, VRAM identical, answer identical.

## Why this is a measurement and not a session artefact

The two runs either side of the JSON run gave 61.44 and 61.67 on the baseline - so the baseline was
behaving normally before and after. The earlier mistake of comparing against a recorded number from another
hour is exactly what this pairing avoids: both arms were run inside four minutes.

## What differs between the arms

`run-json` is the baseline with **one library replaced**: `libllama-common.so.0` from a separate cmake
build, because the baseline's copy predates `json-adapter.cpp`. Everything else - `libllama`, the ggml
libraries, the binary, the model, the request - is identical.

So the cost is attributable to that one library, and the plausible mechanisms are limited: different
compile flags in the other tree, or an ABI difference that turns a direct call into indirection. The
adapter itself is only reached when `FG_JSON_GOOSE_PARSE` is set, which it was not in either arm - so the
cost is not the adapter running, it is the library being a different build.

## The decision, per the rule fixed in advance

The JSON set does **not** become the baseline: -3.4% decode is outside run-to-run spread, and keeping the
speed is the first criterion. The baseline stays as it is, and nothing is published.

## The next step that would settle it

Rebuild `libllama-common` from the **same** tree that produced the baseline `libllama`
(`builds/flint-acc`), so the two libraries differ only by the adapter being present. If the delta collapses,
the cost was a build-flag artefact and the JSON path can join the baseline; if it persists, the cost is real
and the JSON path stays opt-in behind its flag until it is paid for.

That build is two minutes and touches no accepted set - recorded here rather than started, because the
result decides whether the baseline changes.
