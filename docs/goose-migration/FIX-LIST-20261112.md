# Consolidated fix list from the verification work (2026-11-12)

Four defects, all located to a line, all inside the same family of Goose modules (pointwise / pinned-pool), all closed by
one permissioned regenerate-and-rebuild pass. Each was found by measurement, and each has a reproduction that fails while
the defect stands and passes once it is fixed.

| # | defect | location | evidence | fix |
|---|---|---|---|---|
| 1 | SILU scalar tail uses libm `expf` while the wide path uses the bit-exact `avx2_exp_compat`; 247 of 1000 ordinary values differ by 1-2 ULP | `EXP-143/source/pointwise.goose:24-27` (`silu_compat` fallback) | `tools/p2-01-contract` case `silu_1000` | use the same `avx2_exp_compat` association in the fallback |
| 2 | `clamp(NaN)` returns the opposite bound (-0.5 vs native +0.5) | `pointwise.goose:65` - Goose does `min32(max32(a,lo),hi)`, native does `MAX(MIN(x,max),min)` | `tools/p2-01-contract` cases `clamp_t1/t8` | match the native order: clamp upper bound first |
| 3 | `scale(-0)` loses the sign of zero (+0 instead of -0) | `pointwise.goose:62` - `a*k + b` with b=0 gives `(-0)+(+0)=+0`; native skips the addend | `tools/p2-01-contract` cases `scale_t1/t8` | skip the addend when the bias is zero, as native does |
| 4 | pinned-host plan **approves** a zero-byte request while the VMM plan rejects it | `EXP-196/source/host.goose` (plan entry) vs `EXP-195/source/device.goose:34` (`ensure(size>0,10)`) | `tools/p3-17-failures/fixture.c` case `zero size` | refuse zero the way the VMM plan does, or state why not |

## Why one pass closes all four

- 1-3 are in one file (`pointwise.goose`); 4 is in another (`host.goose`), but both are generated by the same compiler run.
- None of them changes the accepted Apex path behaviour that we measured: Apex takes the GLU path (so SILU tail is not on it),
  has no Goose clamp/scale module (native there), and never plans a zero-byte pinned allocation.
- That is exactly why they are safe to fix together: the fixes remove divergences without touching the numbers the accepted
  profile produces. The 32K/128 regression after the rebuild is the acceptance gate, not a formality.

## What must be true for the pass to be accepted

1. `tools/p2-01-contract/build-and-compare.sh` exits 0 - i.e. the divergence set shrinks to norm/softmax/mul_mat/rope or
   fewer, and no new case appears.
2. `tools/p3-17-failures/fixture.c` exits 0 with the zero-size case returning a refusal.
3. Apex regression on the accepted profile: prefill ~2306-2356, decode ~23-24.8, VRAM 3190, `content_equal` with `e68df05b`.
4. The cache ladder is unaffected: cache 3072 still 37.7-39.1 decode at 6266 MiB.

Until the pass runs, all four stay open, the cache path stays experimental, and none of this is called fixed.
