# P8-09: web and UI serving - nineteen doors composed, zero call sites

Checked 2026-11-19 on `main`, text level, no build.

## What is composed

| module | exported doors | in the unit |
|---|---|---|
| `goose/server/web-assets.goose` | 4 | yes (`build-main-runtime.sh:167`) |
| `goose/server/mime-table.goose` | 5 | yes (`:168`) |
| `goose/server/asset-etag.goose` | 2 | yes (`:169`) |
| `goose/server/api-key-policy.goose` | 8 | yes (`:172`) |

Nineteen doors in total.

## Who calls them

**Nobody.** Searching the shipped server sources and the reconstructed runtime for each exported
name returns no call site: `vendor/flint/tools/server/server-http.cpp` has no Goose reference of
any kind, and it is the file that owns static serving, MIME types, ETags, CORS and the API-key
check in the shipped binary. The UI itself is embedded at build time - the build log of this
morning's candidate says `UI: embedded 75 assets` - and served by that same native code.

## What the requirement needs

Switching the serving path to these four modules, then a gate over the same inputs: the asset
table, the MIME lookup, the ETag bytes and the API-key verdict. The differential is well defined
because each door is a pure decision:

- `web-assets`: the asset index and the path lookup, including a miss (the 404 body);
- `mime-table`: extension to content type, including the unknown extension;
- `asset-etag`: the tag for the same bytes, and the conditional-request comparison;
- `api-key-policy`: the verdict for a present, absent, wrong and empty key, and for the "disabled"
  setting.

## What is not claimed

That the interface works through Goose, or that any of this is measured. The nineteen doors are
composed and called by nothing, which is the case rule 33 warns about, and the served path is
unchanged from before the port.
