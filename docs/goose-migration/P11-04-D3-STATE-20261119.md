## Jinja: the conflict is real, and it is already resolved the right way

`goose/jinja/` holds nine tracked modules that export **94 shared names**:

| module | experiment it came from |

| `value.goose`, `value-json.goose`, `builtins.goose`, `lexer.goose`, `parser.goose` | per-slice proofs as well |

`runtime.goose` is the composed successor: it carries the decisions of the per-slice modules with
the names hoisted once. The older files are the frozen proofs of the experiments that produced
each slice, and they cannot be composed together - 94 identical export names, by design, because
each one was verified against the same native rules.

D3's item asks for a merge "done properly, not by renaming identical symbols". That is what
exists: one composed successor in the unit, the per-slice files retained as proofs, the manifest
naming the experiment behind each, and **no renaming anywhere**. What is still open is a manifest
label marking the eight as superseded rather than current, which is a bookkeeping change in
`sync-goose-tree.py`'s canonical table, not a code change.

## Metrics and traces

`goose/metrics/metrics-traces.goose` is in the unit; `goose/metrics/trace-frame-order.goose` is a
separate slice. The metric records are still printed by `runtime/cli/main.cpp:108-111,340`
(`"compute_ms":%.1f`, `"stall_ms":%.1f`, ...), so the formatting on that path is native. P9-07 owns
the CSV/decode-trace/route-trace sinks and stays PARTIAL.

## Stream policy

There is no `stream-policy` module under `goose/misc`; the nearest are
`goose-transfer-policy.goose` and `goose-generated-artifact-policy.goose`, both about build
artefacts, not about streaming. So D3's "metrics and stream policy" is one live item (metrics
formatting) and one that does not exist as a module in this tree.

## Quantization

## Model and session

`goose/model/goose-model-graph.goose`, `goose-model-loader.goose` and `goose/chat/session-loop.goose`
are composed. Their call sites are the reconstructed runtime's loader and the server path; P9-05

in this family: no real-model run after the last change.
