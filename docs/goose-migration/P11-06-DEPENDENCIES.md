# P11-06 — unavoidable dependencies and remaining limits

Status: **DONE** (report, 2026-11-15).

## Unavoidable extern surface

The composed main unit has 99 undefined symbols. They fall into two groups:

| group | count | why it stays external |
|---|---|---|
| libc / libm / POSIX | 34 | allocation, I/O, math, signals, `madvise`, process exit |
| Goose helper entry points | 65 | one adapter function each, implemented in the host: 26 `qz2_*`, 26 `qz_*`, 4 `qd_*`, `gs_json_strtod`, `gs_json_fmt_e`, `gs_frexp_mant`, `gs_strftime_epoch`, `gs_to_string_f64`, `fg458_st_i64`, `fg637_fmt2` |

The helper entry points are not logic gaps: each one is a native primitive the
Goose code calls (a libc-style function, an IQ table view, or a formatting shim).
They are supplied by the adapter generated by `gen_host.py` and by the bridge
objects in the staged builds.

## Data that stays native

- **IQ tables.** `ggml_quantize_init()` tables are `file-static` in
  `ggml/src/ggml-quants.c`. The M1 assembly compiles the unit and adapter into
  `ggml-base` to read them; passing them at init is the open follow-up.
- **GGUF container walk.** The container library reads and validates the file;
  the Goose modules own the decisions (keys, offsets, split naming), not the
  container primitive.
- **Model weights.** The GGUF file itself is input, not code.

## Platform and hardware

- **SIMD kernels.** Goose has no intrinsic surface, so the dot-product kernels
  stay native (the P1-12 decision note records the options).
- **GPU driver / CUDA runtime.** `libcuda`, `libcublas`, NCCL and the CUDA
  toolchain are external by nature; the CUDA artefacts are the build decisions
  (EXP657), not the driver.
- **Apple/Windows branches.** Transcribed but not executed on this host.

## Measurement limits

- Several gates use a transcription of static helpers that cannot be called
  directly; the report cards name them.
- `%.6g`, `%f` and `strtod` depend on the libc; byte parity is claimed only with
  the same libc.
- No model, server or GPU run has been performed by this work; the Apex A/B in
  `APEX-TEST-PLAN.md` is the first planned measurement and needs Igor's approval.
- Batched verify in the speculative gate is not bit-identical to a single pass;
  the gate does not cover it.
- The `iq1_m` and IQ table defects found by the quantized staged builds are fixed
  in the canon (EXP633/EXP644); the `iq1_m` neighbour path is exercised off-grid
  by its own gate.

## What this report does not claim

It does not claim that the runtime is fully migrated: server, chat/Jinja and the
engine call sites are still being switched, and the Apex numbers are the
pre-existing baseline, not a result of this work.
