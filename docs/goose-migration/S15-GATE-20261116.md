# The S1.5 tokenizer gate: what it proves now, and one stale claim in it

Run 2026-11-16 on the current tree. Recorded because the gate is the evidence for three tokenizer
decisions, and its OFF arm no longer means what its comment says.

## What was run

```
g++-13 -O1 -std=c++17 -I<flint>/include -I<flint>/ggml/include -I<flint>/common -I<flint>/src \
  fg_goose_tokenizer_smoke.cpp native-*.cpp -lllama-common -lllama -lggml -lggml-base -lm -pthread
```

Result on the current tree:

```
FG639_SMOKE mode=native vt=146/146 part=20/20 strip=4/16 cases=170/182 failures=12 goose_calls=0 pins=0
```

EXP-639 recorded `strip=16/16 cases=182/182 failures=0` for the same gate.

## The 12 failures are the OFF arm, and the OFF arm is stale

The gate's `run_strip` compares the library's `string_strip` against a reference extraction in the ON
build and against **the input unchanged** in the OFF build, with this comment:

```cpp
// P11-04 D1: the native body is deleted, so an isolation build has no
// strip decision left and answers its input unchanged. Pin that arm
// instead of comparing it with the body it no longer has.
```

That premise is false on this tree:

```
$ nm -C <flint>/build-cuda/bin/libllama-common.so | grep ' T string_strip'
0000000000264920 T string_strip(std::basic_string<...> const &)
```

**The native body still exists and still strips.** So the OFF arm compares a working strip against
"return the input", and 12 of 16 cases differ - all of them leading/trailing whitespace, which is exactly
what a working strip removes.

So the failures are a stale expectation, not a regression in the library. But the stale expectation means
**the gate cannot currently certify the OFF path at all**, and a reader would take `4/16` as a defect.

## What still stands

`vt=146/146` and `part=20/20` - the vocab-type dispatch and the special-token partition still match the
reference extraction in the native build. Those are two of the three decisions.

The third (`string_strip`) is *shown to work* (`got [two\nwords]` from `[ \ttwo\nwords ]` is correct
behaviour) but its OFF arm is asserting the opposite of reality.

## Two ways to fix, and the one that should be taken

1. Restore the OFF arm to compare against the reference extraction, which is what the pristine source
   gives - correct, and it re-establishes `16/16` as the baseline.
2. Delete the native body and keep the pinned arm - correct only **after** the Goose path is the one the
   library actually uses, which it is not: the flag is not wired into `llama-vocab.cpp` on this tree
   (`grep -rn FG_GOOSE_TOKENIZER` finds only the gate, not the runtime).

Option 2 has been written *as if already done*. That is the substitution the project forbids: the
comment describes a state the tree is not in.

## Consequence for the migration status

The three tokenizer decisions remain "ported and proven against a reference extraction"
(`vt`, `part`) plus "ported, native body still live" (`strip`). None of them is switched on in the
runtime, so the tokenizer engine is not closer than the status says.

## Not done here

No edit to the gate and no wiring of the flag. Changing a gate's expectation to match a library is the
move that hides regressions; the expectation should be corrected against the pristine source, and that is
a separate change with its own evidence.
