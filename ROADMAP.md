Предложение старшего помощника после закрытия EXP-044 (не назначенный эксперимент): проверить CPU gather двумя потоками вместо одного, сохранив H2D bytes/calls, ring 32 MiB и checkpoint. Польза — потенциальное сокращение prefill; основание EXP-043: 496,453 мс GPU idle одновременно с gather, не гарантированная экономия. Ближайший предлагаемый gate — безмодельное сравнение одного потока и двух на распределении размеров EXP-043, включая затраты синхронизации, byte parity и последующий H2D. Проверки производительности вручную и последовательно; модельный A/B только по отдельному согласованию. Риски: конкуренция за RAM/cache, занятость CPU, стоимость пробуждений; отсутствие выигрыша закрывает кандидат до модели.

Назначение 2026-09-08: Игорь перевёл это предложение в назначенный эксперимент **EXP-2026-09-08-045 — CPU gather в два потока (безмодельный прототип)**, завершён 2026-09-08 — `INCONCLUSIVE`, итог выше. Единственная переменная A/B: один memcpy против вызывающего потока плюс один постоянный помощник; два pinned slots 16 MiB, диапазон/порядок/число и объём H2D, stream и checkpoint — без изменений. Gate на переход к серверному кандидату: медиана полного времени безмодельной gather+H2D с финальным drain ≥5% сокращения, ≥4/5 побед, все byte-checks, VmSwap=0. Нагрузка — 17 886 диапазонов EXP-032 с однозначным восстановлением mmap-адресов по GGUF-метаданным (21,641 GiB, source footprint ≫ L3). Correctness-гейт пройден: selftest 8/8, побайтовая сверка A/B на реальных диапазонах (sha256 списков хэшей `5bbf98f3…`). Модель и сервер не трогались. Карточка: `experiments/EXP-2026-09-08-045-two-thread-cpu-gather.md`.

## Правило решения

Один эксперимент, одна гипотеза, один baseline, одна основная переменная. Performance ACCEPTED требует ≥3% сокращения median prefill time, подтверждения парными результатами вне наблюдаемого шума и отсутствия неприемлемых регрессий. Меньше H2D calls, работающий код или меньше CPU spin сами по себе не являются успехом. Минимум пять последовательных пар для принятия; ранний отказ при явном провале допустим. Correctness/infrastructure принимаются по своим заранее указанным функциональным критериям без заявления ускорения.

Плохой результат сохранять в журнале, код не включать. `INCONCLUSIVE`, `BLOCKED`, `NOT_RUN` не превращать в ACCEPTED. Handoff обязателен после каждого этапа, включая отказ и блокировку. Запуски модели и коммиты регулирует [AGENTS.md](AGENTS.md); аудит не является разрешением на запуск.
