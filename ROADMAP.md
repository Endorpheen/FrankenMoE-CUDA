Аудит: внешний hard-порог `sys_rate > 2097152` был нерабочим (sys_rate уже MiB/s; внутренний default 2048), сообщение VmSwap в лаунчере завышало MiB в 4 раза (`*4` — лишний page-фактор), `--swap-watchdog` не был включён ни в одном пути запуска. Исправление (порог 2048 + верное KiB->MiB + opt-in `SWAP_WATCHDOG=1`) применено в рабочий `scripts/run_qwen38_server.sh`. Lifecycle: оригинал 4/4 PASS, исправленный 6/6 PASS. Синтетика границ: orig 7/7, fixed 7/7. Модельный smoke (отдельный блок, старший помощник): активация watchdog видна, один запрос 48+35 токенов за 6305,08 мс, MTP acceptance 24/24, CUDA/OOM/trip нет, сервер остановлен. Ограничение: VmSwap=0 формально не достигнут (~150 MiB swap до запроса, за время запроса уменьшился); для functional gate это допустимо. Эти данные не являются performance baseline. `experiments/EXP-2026-09-06-035-watchdog-safety-profile.md`, артефакты в `results/archive/EXP-2026-09-06-035/`.

Отменён до запуска: EXP-030/031/032 уже зафиксировали неизменённый 395-token bulk-prefill path, а EXP-033 содержит сопоставимый control и отклонённый candidate. 4. **R3 / EXP-037 — offline transfer budget и dependency map**. Host pageable submission — доминирующий последовательный компонент. 5. **R4 / EXP-038 — условный bounded pinned ring без packing/scatter**. Status: `ALLOWED` по gate EXP-037 (host submission bottleneck доказан; два ограниченных host slots безопасны по lifetime-карте; ожидаемый net gain 10–35%, центральная оценка ~20% > порога 5%). Два ограниченных host slots, прямые копии в исходные offsets, прежний CUDA stream. Это гипотеза CPU-staging/H2D overlap; истинный H2D/compute overlap не обещать. Старт измерений — только после отдельного approval Игоря (Hard rule 1).
6. **R5 / EXP-039 — условный transfer/compute overlap внутри слоя**. Status: `NOT_RUN` по gate EXP-037: независимое intra-layer окно не доказано — пересечение H2D/kernels = 0 мс и ограничено суммой kernels 438.915 мс (~11% окна), IDs следующих узлов недоступны до вычисления предыдущего split; lifetime destination буфера ясен, но окна нет. Направление `DEFERRED`.
7. **R6 — приёмка конкретного победителя**. Репрезентативный короткий/основной/длинный prompt, decode, повторные запросы, cancellation/checkpoint/shutdown. Только затем patch доставки и предложение изменения default. Нет победителя — сохранить baseline и закончить с отрицательным результатом.

Если R4 принят, сначала R6. R5 начинается отдельным циклом только после handoff и лишь при оставшемся измеренном bottleneck. R4 и R5 не реализуются одновременно.

## Правило решения

Один эксперимент, одна гипотеза, один baseline, одна основная переменная. Performance ACCEPTED требует ≥3% сокращения median prefill time, подтверждения парными результатами вне наблюдаемого шума и отсутствия неприемлемых регрессий. Меньше H2D calls, работающий код или меньше CPU spin сами по себе не являются успехом. Минимум пять последовательных пар для принятия; ранний отказ при явном провале допустим. Correctness/infrastructure принимаются по своим заранее указанным функциональным критериям без заявления ускорения.

Плохой результат сохранять в журнале, код не включать. `INCONCLUSIVE`, `BLOCKED`, `NOT_RUN` не превращать в ACCEPTED. Handoff обязателен после каждого этапа, включая отказ и блокировку. Запуски модели и коммиты регулирует [AGENTS.md](AGENTS.md); аудит не является разрешением на запуск.
