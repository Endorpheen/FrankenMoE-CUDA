## 5. How the flag is wired

Four call sites, two files.

`ggml/src/gguf.cpp` — the three writer entry points keep their bodies and gain
`*_native()` names:

```cpp
void gguf_write_to_buf_native(const struct gguf_context * ctx,
                              std::vector<int8_t> & buf, bool only_meta) {
    gguf_writer_buf gw(buf);
    gguf_write_out(ctx, gw, only_meta);
}

void gguf_write_to_buf(const struct gguf_context * ctx,
                       std::vector<int8_t> & buf, bool only_meta) {
#ifdef FG_GOOSE_GGUF
    if (fg_gguf_goose_write(ctx, buf, only_meta, fg_goose::ENTRY_WRITE)) return;
    GGML_ABORT("FG_GOOSE_GGUF: the Goose GGUF writer refused the context");
#else
    gguf_write_to_buf_native(ctx, buf, only_meta);
#endif
}
```

`gguf_get_meta_size` and `gguf_get_meta_data` follow the same shape with
`only_meta = true`. `tools/gguf-split/gguf-split.cpp` selects the plan:

```cpp
bool should_split(int i_tensor, size_t next_size) {
#ifdef FG_GOOSE_GGUF
    const int64_t rc = fg_goose::should_split((int32_t) params.mode, i_tensor, n_tensors,
                                             (int64_t) next_size, params.n_split_tensors,
                                             (int64_t) params.n_bytes_split);
    if (rc < 0) GGML_ABORT("FG_GOOSE_GGUF: the Goose split plan refused the parameters");
    return rc != 0;
#else
    ... the original predicate ...
#endif
}
```

The staged `CMakeLists.txt`:

```cmake
if(FG_GOOSE_GGUF)
    add_library(fg-goose-gguf OBJECT goose-gen/gguf-stack.c)   # one object unit
    set_target_properties(fg-goose-gguf PROPERTIES C_STANDARD 11 POSITION_INDEPENDENT_CODE ON)
    target_compile_options(fg-goose-gguf PRIVATE -w)
    target_sources(ggml-base PRIVATE common/fg-goose-gguf-bridge.cpp)
    target_compile_definitions(ggml-base PRIVATE FG_GOOSE_GGUF=1)
    target_link_libraries(ggml-base PRIVATE fg-goose-gguf)
endif()
```

Properties that matter for the production rule ("a new feature's flag exists
only to disable it"):

- OFF is the default; the OFF library is byte-identical to the base library
  (`304d6da2…` for both), so switching the flag off is a rebuild, not a revert;
- no translation unit is edited at run time and no native call is deleted: the
  native bodies, including `gguf_write_out`, stay compiled in the ON library;
- the base build of this tree is possible without the staged project at all,
  because the only unconditional edit is the `*_native()` rename of three
  entry points, which is inert without the flag.

The four call sites replaced by Goose:

| native call | Goose export | how the host reaches it |
|---|---|---|
| `gguf_write_to_buf` | `s3_write(..., only_meta=0)` | full header + KV + descriptors + data section |
| `gguf_get_meta_size` | `s3_write(..., only_meta=1)` | length of the metadata section |
| `gguf_get_meta_data` | `s3_write(..., only_meta=1)` | the metadata bytes |
| `split_strategy::should_split` | `gsp_should_split` | the plan decision per tensor |

The writer path also passes through the module's own setters (`s1_set_val`,
`s1_set_str`, `s1_set_arr`, `s1_set_arr_str`, `s3_init_tensors`,
`s3_add_tensor`), so the KV order, the "set an existing key removes then
appends" rule, the reserved `general.alignment` rule, `ggml_n_dims` derivation
and the cumulative padded offsets are the module's, not the host's.

## 6. Results

### 6.1 Writer gate (`tests/fg_gguf_smoke.cpp`)

Fourteen synthetic contexts built through the public `gguf` API only: empty;
every scalar type; numeric and bool arrays; string arrays; a key set twice; a
key removed and re-added; `general.alignment` as a KV while the context
alignment stays 32; one 2-D F32 tensor; F16 and I8 tensors; Q4_0 and Q8_0
tensors; a 4-D tensor; three tensors with unequal sizes (the padding chain); a
64×64 F32 tensor; and a 64-byte-aligned context produced by the native reader.

Per case the gate compares the full byte image, the metadata size and the
metadata bytes: 41 comparisons. The ON build adds 14 plan checks (seven
scenarios, count and ranges) that compare `gsp_split_layout` with a replay of
`gsp_should_split`, so 55.

```
FG630_SMOKE mode=native cases=14 checks=41 failures=0 goose_calls=0
FG630_SMOKE mode=goose  cases=14 checks=55 failures=0 goose_calls=394 (write=13 meta_size=14 meta_data=14 split=347 layout=6)
```

The 64-alignment case compares metadata only: a reloaded `gguf_context` leaves
`ggml_tensor::buffer` uninitialised (the reader never zeroes it, and no public
setter exists), so a full-data write of such a context dereferences garbage in
the native path as well. That is a pre-existing native landmine, not a Goose
difference; the gate does not hide it (see section 7).

Two honest notes on the mutation set:

1. **A1 was first written as the module's remove-then-append rule** (append the
   new record before dropping the duplicate). It came back UNDETECTED, and the
   reason is a real property of this seam: the adapter replays an already
   deduplicated `gguf_context::kv` list, so `drop`/`s1_remove` never fires on
   the runtime path. A1 now mutates the emission order instead, which is what
   the wire actually exposes. The finding is recorded in section 7.
2. **B6 is caught by the plan-consistency check**, not by the native split
   gate: no runtime caller consumes `gsp_split_layout` yet, so its ranges are
   compared against the module's own predicate replay. The other eleven are
   caught against native bytes.

## 7. The seam this stage cannot remove

The Goose module does not own `struct gguf_context`. That struct
(`std::vector<gguf_kv>` of `std::string` + `std::vector<int8_t>`, tensor infos
with a `ggml_tensor`, alignment, version) is private to `gguf.cpp` and no ABI
exposes it, so the host still walks it:

1. `common/fg-goose-gguf-adapter.inl` (about 90 lines, included by `gguf.cpp`)
   turns the context into plain views: key, type, array flag, element image or
   C string list, tensor name, `ne[]`, `ggml_n_dims`, type, data image. For a
   backend tensor it stages the bytes through `ggml_backend_tensor_get`.
2. `common/fg-goose-gguf-bridge.cpp` (about 300 lines) builds the module's flat
   arrays from those views and calls `s1_*`/`s3_*`.

This is the honest price of the slice: the module owns the wire format, the KV
list semantics, the offsets and the plan, while the host owns
"gguf_context -> view".

Consequences recorded for the next slice:

0. **The mutating API is where the KV semantics disappear.** The runtime path
   feeds the module an already deduplicated `gguf_context` (native setters
   replace a key in place), so `drop`/`s1_remove` never executes there and the
   "set an existing key removes it and appends" rule is unobservable: the first
   A1 mutation in section 6.4 proved it by staying UNDETECTED. Until
   `gguf_set_kv`/the setters are switched too, that rule is covered only by the
   module's own gate (EXP571/596), not by this build.

1. **Scratch per call.** Every call allocates the KV arrays (eight `int64`
   vectors of `max(n_kv,1)`), the byte pools sized from the views, the tensor
   arrays and an output buffer of the exact upper bound, then resizes. Correct,
   but not acceptable on a request path; a pooled arena is needed before any
   server wiring. (A full write of the 128-tensor, 2.1 MB split input
   allocates one output buffer of that size plus the pools; the metadata-only
   calls the split tool makes allocate a few kilobytes.)
2. **Refusal is an abort.** The public calls `GGML_ABORT` when the module
   returns `-1` (a removed ggml type, a broken reserved-key rule, a data image
   that does not match `nbytes`, an alignment that is not a power of two).
   Native asserts in most of the same cases, but there is no differential gate
   on invalid contexts, so "same failure mode" is not proven.
3. **The reloaded-context landmine.** `gguf_init_from_file` leaves
   `ggml_tensor::buffer` uninitialised; the writer's `if (info.t.buffer)` then
   calls `ggml_backend_tensor_get` on a garbage pointer. The Goose path reads
   the same field through the view and inherits it. Fixing it belongs to the
   reader, not to this stage; the gate documents it instead of hiding it.
4. **The reader stays native.** `gguf_init_from_file`,
   `gguf_init_from_buffer`, `gguf_init_from_callback` and every getter are
   untouched, so load parity is not part of this slice.
5. **Only the plan is switched in the split tool.** `gsp_split_layout`,
   `gsp_split_write` and `gsp_merge` have no runtime caller: the tool's
   constructor loop, its per-shard writer and `gguf_merge` stay native, and the
   tool writes the tensor data section itself. What the ON tool proves is that
   `should_split` (the decision) and the metadata writer agree with native.
6. **`gguf_set_kv`/`<`setter>` semantics on the write path only.** The bridge
   replays the context through the module's setters, but the *mutating* API of
   the runtime (`gguf_set_val_*`, `gguf_add_tensor`, ...) is still native; only
   the bytes come from Goose.
7. **Gate convention.** The repository expects gates at `-O1`; both gates link
   the Release library and the generated Goose object is compiled at `-O2`
   with `-w`.
8. **Model-level parity.** Not attempted: no server, no model, no GPU. The
   saver path (`llama_model_save_to_file` -> `gguf_write_to_file` -> the Goose
   writer when the flag is on) is exactly what a model A/B would exercise, and
   that needs Igor's approval and the GPU runtime.

## 11. What is still open

1. **The host seam.** `gguf_context -> views` is not Goose and cannot be
   without an ABI decision (an opaque accessor, a Goose-side `gguf_context`
   model, or a module entry point that takes the context layout). That is the
   main open shim of this slice.
2. **Scratch buffers.** Per-call allocation; needs a reused arena, and the
   output buffer should be sized once instead of bounded and resized.
3. **Failure parity.** No differential gate on invalid contexts: removed ggml
   types, non-power-of-two alignments, tensors without data. Today the ON path
   aborts where native asserts.
4. **Reader and getters.** Not switched; load parity unproven.
5. **Rest of the split module.** `gsp_split_layout`, `gsp_split_write`,
   `gsp_merge`, `gsp_split_name` and `gsp_parse` have no runtime caller; the
   tool keeps its own layout loop, shard writer and merge.
6. **Mutating GGUF API.** `gguf_set_*`, `gguf_add_tensor`, `gguf_remove_key`
   are still native; only the emitted bytes come from Goose. Consequence: the
   module's duplicate-key rule (`drop`/`s1_remove`) is unreachable on this path
   and stays gated only by the module's own experiment (see section 7, item 0).
   The mutation set therefore cannot cover it, and a future slice that switches
   the setters must add that mutation back.
7. **Model-level parity.** The saver path is now behind the flag; proving
   "identical model output for the same request" needs the GPU runtime, a real
   model, and Igor's explicit approval. Nothing in this stage claims a step
   toward that yet.
8. **Gate convention.** `-O2` (Release) instead of the repository's `-O1`,
   because both gates link the release library.
