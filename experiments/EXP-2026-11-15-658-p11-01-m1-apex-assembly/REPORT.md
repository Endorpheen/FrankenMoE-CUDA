### 2.2 The unit

Composed with the repository's own script, unchanged:

```
bash tools/build-main-runtime.sh /tmp/opencode/sub-659/unit
  → [1/5] compose 98 modules
  → composed 99 module(s) → main.goose (3,139,685 B)
  → typecheck ok, `goose --standalone` → main.c (18,220,772 B), main.h (125,274 B)
  → gcc-13 -O1 -std=c11 -w → main.o (4,640,792 B)
  → main runtime ok: 854 global symbols, 0 duplicates, 99 extern
```

99 extern = 34 libc/pthread + 65 Goose helpers. The analysis predicted 64
helpers; at `050354e9` there is one more, `mp_fmt_f1` (moe-predict-report). The
composer fix from Step 0 of the plan is already in this commit
(`rename_text()` skips string literals), so there is **no `op_sqrt`** and the
99 externs are all real.

### 2.3 The one host adapter

`host/goose_host.c`, generated by `/tmp/opencode/sub-659/gen_host.py` from the
unit's own prototype block, so the signatures cannot drift:

- 51 symbols: 42 quant primitives (`qz_`/`qz2_`/`qd_` load/store/libm/bit
  views/scratch/IQ1 sort, lifted from `EXP-635`) and 9 named helpers
  (`gs_json_strtod`, `gs_json_fmt_e`, `gs_frexp_mant`, `gs_strftime_epoch`,
  `gs_to_string_f64`, `mt_fmt_g6`, `mp_fmt_f1`, `fg637_fmt2`, `fg458_st_i64`,
  lifted from the accepted fixtures named in the file header);
- **one** `pthread_once` (`fg_goose_host_ensure_init`), plus
  `fg_goose_host_init_runs()` so the property is measurable, not assumed;
- fp16 conversion is the tree's own algorithm copied from `ggml-impl.h`, so the
  adapter has no ggml dependency;
- 14 IQ table views cannot live here (the tables are file-static in
  `ggml-quants.c`) and are appended there instead, guarded by
  `FG_GOOSE_RUNTIME`.

Every bridge was changed from its own `std::call_once` guard to a call to
`fg_goose_host_ensure_init()`: eight guards in total became one. Two duplicate
host hooks were removed from bridges that carried their own copy
(`gs_json_strtod` in the tokenizer bridge, `mt_fmt_g6` in the metrics bridge),
and the quant bridge lost the 54 primitives it redefined, keeping only its three
dispatch entries.

## 8. Deviations from the plan, and why

1. **The unit and the adapter are compiled into `ggml-base`, not into a library
   of their own.** The unit reads the native IQ tables through 14 entry points,
   and those tables are file-static in `ggml/src/ggml-quants.c`; a separate
   target would make `ggml-base` and the runtime mutually dependent, which is a
   static-library cycle (resolvable with `--start-group`, not with a clean
   target graph). `ggml-base` is already on the link line of `llama`,
   `llama-common` and every gate, so hosting the objects there keeps one copy of
   `goose_init` and no cycle. This is the structural seam M1 leaves open.
2. **The IQ accessor guard in `ggml-quants.c` became `FG_GOOSE_RUNTIME`.** The
   accepted EXP-635 patch guards them with `FG_GOOSE_QUANT`, but the composed
   unit references them regardless of which flag is on, so any ON build would
   fail to link with only QUANT off.
3. **Three bridges lost code they duplicated**: the tokenizer bridge's
   `gs_json_strtod`, the metrics bridge's `mt_fmt_g6`, and the quant bridge's 54
   primitives. The adapter owns them now; keeping both copies was a duplicate
   definition at link time (found by the linker, exactly as R-2 predicts).
4. **The tokenizer bridge lives in `llama.cpp/src/`**, because the S1.5 patch of
   `common/common.cpp` includes `../src/fg-goose-tokenizer-bridge.h`. The
   accepted CMake also put it there; my first copy in `common/` broke the build.
5. **`LLAMA_BUILD_TOOLS=ON`** to get a `llama-server` target (see §3).
6. **The unit is the base commit's module list, not the current one.** Parallel
   work advanced HEAD from `050354e9` (98 modules) to `9f5e2adb` (107 modules)
   while M1 ran: nine modules were added (`cli-driver-loop`, `cpp-headers`,
   `device-headers`, `mtp-capture-warmup`, `sampler-chain`, `sched-eval`,
   `server/api-key-policy`, `cors-policy`, `query-transport`) and
   `goose/chat/jsonparse.goose` left the list. The unit was composed from
   `050354e9`'s list and reproduces from it exactly; it is *not* the unit a
   fresh run at HEAD would produce. See R-6.

## 9. What is left for the stage

- **Step 4** of the plan: the six side libraries are still side libraries
  (S1.4, S1.6, S2.1, S2.2, S3.1, S3.2). Their engine call sites are proposals,
  and S3.1 still has no carrier in this tree. M1 proves they coexist; it does
  not prove they substitute anything in the engine.
- The unit's home: move it out of `ggml-base` once the IQ table view is passed
  at init instead of linked (`FG_GOOSE_RUNTIME` would then be one target with no
  cycle).
- The repository's own bookkeeping: 87 in `RUNTIME-INTEGRATION.md`, 98 modules
  at `050354e9`, 107 at HEAD `9f5e2adb`, and `dist/manifest.json` recording
  84 / 765 globals against the current 854. Four numbers, four sources; M1's
  numbers are 98 listed / 99 composed / 854 globals / 99 extern / 65 helpers.
- Per-flag ON in isolation (one flag at a time) was not run. M1 ran all-OFF and
  all-ON, which is what the increment asks for; a per-flag sweep is the next
  cheap check.
- No performance number, by construction: S1.3 changes the decode path and its
  cost belongs to P11-02 with the A/B protocol.
