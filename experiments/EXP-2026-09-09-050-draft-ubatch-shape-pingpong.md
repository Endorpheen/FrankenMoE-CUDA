- target verify (3,3): reuse 115, rebuild 2 (граница после prefill) → **98% reuse**;

- draft generate #1 (1,1): rebuild 117/117, reason `params:ubatch.n_tokens 3->1`;

- target-бэкенд: 49 ключей-сплитов (n_nodes=113, по одному на MoE-слой) — после первого
  захвата launch на каждом шаге (113–116/117), сбросов нет → **replay полный**;

## Метрика сервера «graphs reused 56/171» расшифрована

task 0 печатает 56, task 59 печатает 171, и 171−56 = 115 — ровно число (3,3)-reuse
измерительного сегмента. Счётчик кумулятивный и считает только target-контекст. Дробь
«56/171» из EXP-049 — misreading двух снимков одного счётчика: reuse target verify не 33%,
а 98%. Экспектация «низкого reuse у target» снята — дыра находится в другом месте.

## Причина (главный ответ)

**Чередование форм убатчей в драфт-контексте MTP: catch-up принятых токенов (n_tokens=3) и
генерация драфта (n_tokens=1) идут через одну цепочку результатов графа и один бэкенд —
форма меняется при каждом вызове.** Места:
- L1: `llm_graph_params::allow_reuse` требует равенства `ubatch.n_tokens`
  (src/llama-graph.cpp:1487), вызов из `llama_context::process_ubatch`
  (src/llama-context.cpp:1419) → 2 из 3 убатчей драфта перестраивают граф каждый шаг;
- L2: ключ CUDA-графа = `cgraph->nodes[0]` (ggml/src/ggml-cuda/ggml-cuda.cu:4605),
  идентичность свойств — memcmp `node_properties` вкл. `node[0].ne` (ggml-cuda.cu:2927),
  warmup требует ≥2 подряд одинаковых вызовов (ggml-cuda.cu:4627–4634): флип `ne[1] 1↔3`
  (и `ne[2] 0↔1`) каждый вызов не даёт warmup сойтись никогда.
Target-контекст на обоих уровнях не затронут (98% L1-reuse, 100% L2-replay).

Стоимость на спекулятивный шаг (диагностика, не заявление ускорения): драфт-бэкенд —
2 прямых исполнения 179 узлов (116+63) + один capture с instantiate, чей instance гибнет на
следующем шаге; плюс 2 полных L1-ребилда графа драфта.

## Направления устранения (решение за Игорем, ничего не реализовано)

(a) catch-up тремя убатчами по 1 токену — все вызовы драфта становятся формой 1: цепочка L1
стабилизируется, warmup L2 сходится со второго шага, далее чистый replay; семантика меняется
незначительно (3 последовательных прохода вместо одного батчевого), эффект по скорости —
только измерением в отдельном EXP;
(b) пространство имён для результатов графа / ключей CUDA-графа по хэшу формы вместо
указателя nodes[0];
(c) оставить как есть.
