# Goose CPU backend research checkpoint

Production verdict: **REJECTED for promotion**. The working runtime is unchanged.
This is a retained engineering checkpoint, not a stopped migration or an accepted
performance improvement. Exact NaN payload compatibility and performance remain
open. Continue the larger isolated migration from this evidence.

## Implemented computation

- Whole raw Q4_K/Q6_K MoE controller: Q8_K conversion partitions, grouping supplied
  expert IDs, worker/expert iteration, atomic work-claim policy, matrix tiles,
  output addressing and scatter.
- Complete raw Q4_K/Q6_K tiled-prefill: weight unpack/scales/bias correction,
  activation gathering/bias/padding, SIMD microtiles, explicit FMA epilogues,
  K accumulation, narrow/standard windows, thread partition and scatter.
- All computations supported by the original binary-ops.cpp and unary-ops.cpp:
  four binary and23 unary operations, seven binary/five unary F32/F16/BF16 type
  combinations, broadcasting, strided views, thread ranges, BF16 rounding and
  stores. Checked F32x8 views accelerate compatible large binary operations;
  the other layouts/types still execute Goose scalar code.

Goose computation is generated by the self-hosted compiler, not wrappers around
the original C++ math functions. Native atomic/barrier/threadpool/physical memory
services, elementary FP16/libm primitives and tensor metadata bridges remain.
Other quantizations, repack, router softmax/top-k, GELU/SiLU/GLU elsewhere in
ops.cpp and the rest of GGML CPU/CUDA/application code are not claimed ported.

## Retained failures and producer identities

- Flat/unshaped and scalar versions, slower Q6/tiled candidates and all timings.
- Conditional float literals rejected until explicitly cast to f32.
- Reserved loop identifier block rejected before compilation, renamed chunk.
- Sanitized implicit XIELU expression differed at3900 non-NaN outputs. Native
  assembly uses a final FMA; explicit source fmaf eliminates those differences.
- NaN payload differences remain; original exact-failure artifacts are preserved.
- An ngl0 mixed-offload Apex profile failed at CUDA buffer upload while new tiled
  math was disabled but older Goose graph/allocation remained active. Full CPU
  isolation passes. Precise cause is open, not assigned to the compiler/language.

## Snapshot and local reproduction

Source, emitted C, original reference files, ABI bridges, deterministic fixtures,
selected build/generation commands, complete text timing/diagnostic records and
synthetic model requests/responses are included. The original GGML sources retain
their MIT license in reference/LLAMA-GGML-MIT-LICENSE. The only source normalization
is three absolute bridge-header includes made relative in two alternate CPU C files.
Goose and emitted C bytes are unchanged from the tested artifacts.
The frozen unary C++ reference retains its historical blank line at EOF; a
file-scoped Git whitespace attribute preserves that exact reference snapshot.

Model weights, compiler/runtime/object binaries and numeric .bin corpus dumps
remain local; omitted corpus dumps have SHA256/size records. Private instruction
files, local feedback and migration policy notes are excluded.

Run `python3 tools/verify_snapshot.py` for payload hashes and relative include
closure. This is an integrity check, not an inference correctness test.

On the original host, run `python3 tools/rebuild_local.py`. It compiles the ten
selected snapshot compute/bridge/reference units, links them with the recorded
unchanged GGML baseline objects, and replays the real1225 binary/unary plus114
tiled GGML graphs. It requires the exact local frozen source/libraries from the
recorded experiment root. Builds use a temporary directory under
/home/end0/AI/LlamaServer. It does not start a model, modify defaults or rebuild
the compiler. The local baseline dependency is explicit: this is not a portable
standalone FrankenMoE installer. As-run orchestration snapshots are historical
records; some generators derive other helper files and are not a single-click
reproduction pipeline.

All nine unchanged original runtime hashes are recorded in results. The full
CPU MoE/CPU backend/CUDA/scheduler/application goal remains unfinished.
