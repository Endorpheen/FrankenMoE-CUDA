What stays where it was, deliberately:

* W1 keeps the git index read, the 512-byte head truncation, the messages and the

* W2 keeps the file system, `cmake` itself and `cmake --build`; nothing about

* W3 keeps `git`, `gh`, `stat`, archive creation and SHA-256 hashing; the module
  composes documents from hashes the script computed, as it always did.
* W4 keeps `gguf`, `numpy`, the metadata calls and the byte writing; the plan —

`runtime/tests/CMakeLists.txt` consumes W4 without a line of its own: the two

## Transport

`tools/goose-hosts/` holds one host per module (`art`, `env`, `pkg`, `fx`) plus a
shared header, a shell client and a build script. Each host links
`build/goose-hosts/<name>.c`, generated from the accepted module with no edit to
it, and speaks one request per line:

```
GEN <path-hex> <head-hex>      -> OK 0|1
SUMS <n> <hash-hex> <name-hex> ...  -> OK <hex of the file body>
```

A missing host binary is not fatal: the caller prints one line on stderr and
uses its inline code, so a fresh clone can run the hook and the fixture
generator before anything is built. This was checked by moving `art` aside.

## Gates

Each gate compares the wiring with the previous behaviour over the corpus the
accepted experiments already pinned, and requires 0 disagreements.

```
FG663_ART_CORPUS rows=23 values=23 failures=0
FG663_ART_E2E    rows=14 values=28 failures=0
FG663_ENV_CORPUS rows=27 values=27 failures=0
FG663_ENV_E2E    rows=12 values=36 failures=0
FG663_PKG_CORPUS rows=73 values=73 failures=0
FG663_PKG_E2E    rows=6  values=6  failures=0     (see the note below)
FG663_RELEASE    rows=12 values=24 failures=0
FG663_FX         rows=12 values=131 failures=0
```

* `ART_CORPUS` — the P10-05 S3 `generated/limit/gate` rows (23), each evaluated
  through the host and through the script's own inline branch.
* `ART_E2E` — 14 staged trees in a scratch git repository, the real script, both
  modes: identical exit code and identical stdout+stderr, including the
  `--all`/`--mb` paths, `.cuh` naming, mixed trees and the 1 MiB boundary.
* `ENV_CORPUS` — the P10-05 S2 `dir/jobs/args/build_type/subdirs` rows (27)
  against the executable oracle (`bash`, `cmake -P` on the pinned native copies).
* `ENV_E2E` — the real `build.sh`, 12 environments (default, set, empty, spaces,
  relative, text `JOBS`, renamed generator, overrides), with the upstream clone
  step neutralised and a recording `cmake` on PATH: identical argv, stdout and
  exit code in both modes.
* `PKG_CORPUS` — the whole P10-05 S1 table (73 rows) against the executable
  oracle; `SHA256SUMS` and `manifest.json` are compared as bytes.
* `PKG_E2E` — `tools/package-main-runtime.sh` in both modes: the dist listing,
  the two documents and the copied products.
* `RELEASE` — `scripts/make-release.sh` dry run in both modes, 12 cases: valid
  tags including `-rc.1`, four malformed tags, a missing notes file, a missing
  asset, a sparse 3 GiB asset over the GitHub limit, plain and runtime assets.
  Nothing is tagged or pushed; the apply path is not exercised.
* `FX` — the real generator, 12 parameter combinations (both architectures,
  splits 1/7/10/13/20/51/100, three refused gemma4 splits): file-for-file
  SHA-256 equality of every gguf written, plus banner and stderr equality.

Two notes on `PKG_E2E`, both from the first runs of this arm:

1. It found a real defect: the off branch had lost the `cp` of the four build
   products, so the previous behaviour was not preserved (1 of 6 values passed).
   It was fixed and the arm re-run: 6/6.
2. The two modes must share one output directory. Two independent builds of the
   composed unit differ in `main.goose` by the path they were built at, which
   makes three values differ for a reason that has nothing to do with the
   wiring. The arm therefore builds twice at the same path and snapshots the
   dist between the runs.

The full `w3_pkg.py` run takes about ten minutes because of those two builds;
`--skip-e2e` runs the 73-row corpus arm only (`results/gate-w3_pkg.log`).

Two entries written for this experiment were **equivalent mutants**, not gate
holes, and were replaced rather than counted: shortening the banner prefix
`"… compiler from "` to `"… compiler from"` cannot change a prefix test, and
`mb_milli < 0` → `< 1` cannot change a product. The replacements
(`from` → `for`, and "an unbannered `.c` counts as generated") are caught by the
corpus arm.

Half 1 for `art`/`env` also reuses the accepted P10-05 table entries that touch
the wired exports; the entries for `tools/check-goose-tree.py` and
`prepare_upstreams.sh` were left out on purpose, because this wiring does not
call those exports and a survivor there would say nothing about the gate.

## What remains

1. **`tr_` is blocked by the toolchain, not by the wiring.**
   `goose/misc/test-runner.goose` exports `tr_match` and `tr_selected` with a
   `bool` return and slice parameters; `goose --standalone` and `goose check`
   both refuse the module:

   ```
   goose/misc/test-runner.goose:291: error: export fn tr_match:
       could not resolve one concrete function signature
   goose/misc/test-runner.goose:314: error: export fn tr_selected: ...
   ```

   Four attempts were made: an appended shim with `i64` wrappers that call both
   exports with concrete `const u8[:]` types, then an appended `main()`, then
   `goose build` and `goose check` instead of `--standalone`. All four fail the
   same way; only
   `goose run` accepts the module, which is how the P10-09 gate exercised it. A
   C host therefore cannot exist without a two-line module amendment (return
   `i64`, or drop `export` on the two functions and keep the wrappers). That
   amendment re-opens an accepted slice, so it is the lead's call, not this
   experiment's.
2. **`dg_` has no native file at this base.** `goose/metrics/bench-diagnostics.goose`
   names `scripts/bench-analyze.py` and `scripts/trace_io.py`, but neither exists
   in the tree at `0da127f5` (`git ls-tree -r 0da127f5 --name-only | grep -E
   'bench.?analy|trace_io'` is empty; the only copies are the pinned oracles
   inside `experiments/EXP-2026-11-15-652-p10-09-test-runners/dg/tests/native/`).
   There is no caller to wire in this repository until the analyzer lands.
3. Unused exports of the wired modules: `art_required_*`, `art_manifest_mask`,
   `art_orphan`, `art_verdict` (`tools/check-goose-tree.py`), and `env_pin_ok`,
   `env_integration_state`, `env_link_guard`, `env_markers_all`,
   `env_option_table`, `env_upstream_pins` (`prepare_upstreams.sh`,
   `runtime/CMakeLists.txt`). Same reason as the mutation filter above: the
   scripts that own them are a separate wiring decision.
4. `fx_meta_count`/`fx_meta` and `fx_shards` are not called by the generator: the
   metadata table is still written by hand and the shard count is not asserted.
   The plan and the banner are wired; the metadata order is gated but driven
   natively.
5. `bench-analyze.py` itself (see 2) plus `tools/check-goose-tree.py` would be the
   next two wirings, in that order, once their native owners exist in-tree.
