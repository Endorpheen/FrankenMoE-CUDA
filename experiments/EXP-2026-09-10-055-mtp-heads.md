# EXP-2026-09-10-055: alternative MTP draft heads

Status: REJECTED (kind=model-ab, closed 2026-09-10). No alternative head beats
the accepted current head beyond run-to-run noise; no runtime or launcher change.
Kind: isolated A/B of draft-head artifacts.
Owner: Igor. Implementation: OpenCode agent.

## Hypothesis recorded before measuring

The accepted runtime uses one MTP sidecar
(`models/qwen38/MTP/mtp-Qwen3.8-Flash-Next-Q4_K_M.gguf`, sha256
`4563303ab6e7d40f409750fd48af76bf33dd76b0773951cbf484109107de8140`). Other
Flash-Next MTP heads are published by unsloth (self-contained and shared,
Q4_K_M/Q8_0/BF16) and dzannotti (Q4_K_M on stock quant types). A different
head may decode faster at equal or better acceptance because the draft step is
dominated by the shared output projection and by the head's own MoE, and its
quantization changes both cost and agreement with the quantized target.

Goal: find a head that raises decode tok/s over the current one, or document
that none does.

## Scope

- Fixed context (start 8192), fixed prompt, temperature 0, warmup then a
  256-token request, one server process per head, accepted EXP-046 runtime.
- MTP `--spec-draft-n-max 2` first; then `3` and `--spec-draft-p-min 0.75` for
  the best head only.
- Same binary `build/exp046-default-runtime/bin/llama-server` for every arm.
- No change to target, launcher, baseline, quantization or KV settings.

## Non-goals

- No training, no reduced-vocabulary head, no DFlash/Edge0.
- No concurrency and no aggregate throughput.

## Gates

- Same prompt bytes, warmup, 256 output tokens, temperature 0.
- Report decode tok/s (predicted_n / predicted_ms), draft acceptance, mean len.
- A head is interesting only if decode speed exceeds the current head beyond
  run-to-run noise while acceptance does not collapse.

## Results (2026-09-10, run by OpenCode)

Runtime `build/exp046-default-runtime/bin/llama-server`, exact EXP-046 profile,
ctx 8192, MTP `--spec-draft-n-max 2`, prompt 59 tokens ("Explain how a four-stroke
internal combustion engine works in about 150 words."), 256 greedy tokens, the
same prompt bytes for every arm. `decode_tok_s = predicted_n / predicted_ms`.
Temperature 0 makes acceptance, mean accepted length and the answer deterministic;
only decode speed varies between runs. The first run of a session is a cold
outlier and is excluded (the current head gave 13.71 tok/s cold, then 20.93 in the
same session).

First sweep, one run per head, warm:

| head | decode tok/s | acceptance | mean len |
| --- | --- | --- | --- |
| current (Q4_K_M) | 20.93 | 0.69811 (148/212) | 2.40 |
| dzannotti (Q4_K_M) | 19.84 | 0.70952 (149/210) | 2.42 |
| shared-Q4_K_M | 20.89 | 0.67593 (146/216) | 2.35 |
| self-Q8_0 | 19.38 | 0.68692 (147/214) | 2.37 |

Confirmation sweep, two runs per head, warmup excluded, median:

| head | decode tok/s | runs |
| --- | --- | --- |
| dzannotti | 21.79 | 22.404, 21.185 |
| current | 21.12 | 21.111, 21.126 |
| shared-Q4_K_M | 20.67 | 20.465, 20.876 |

Paired duel, four rounds with the launch order alternated (cur,dz -> dz,cur ->
cur,dz -> dz,cur), warmup excluded:

| head | median tok/s | mean | runs |
| --- | --- | --- | --- |
| current | 20.860 | 20.849 | 20.449, 20.949, 20.770, 21.227 |
| dzannotti | 20.839 | 20.843 | 20.598, 21.094, 20.674, 21.004 |

Acceptance over the whole duel: current 0.69811 (148/212), dzannotti 0.70952
(149/210); mean accepted length 2.40 vs 2.42. The two heads are statistically
indistinguishable in decode speed (median difference 0.1%, ranges fully
overlapping); dzannotti leads acceptance by one accepted token on this prompt,
which is not a usable margin.

The emitted answers are identical across every head and every run. Speculative
decoding verifies each proposed token against the target, so the head changes
draft cost and acceptance only, never the text.

`shared-Q8_0` could not be measured: the downloaded file sha256 is
`499c1104df25c19f...`, not the published `5ff54097406a905c...`, so the file is
corrupted and was excluded. `dzannotti` is a third-party repack of the same
`qwen4exp` head; the only structural differences from the current head are the
output-projection quant (Q4_K vs Q6_K, the ~163 MB size difference) and the
absence of `blk.48.nextn.shared_head_norm.weight`.

## Verdict

REJECTED as a speed candidate. No alternative head beat the accepted current head
beyond run-to-run noise. The closest alternative (dzannotti) ties the current head
at about 20.8-20.9 tok/s in the alternating duel (median 20.839 vs 20.860, -0.1%);
shared-Q4_K_M and self-Q8_0 are slower. The accepted current head stays; the
runtime and the launcher do not change. The decode bottleneck is the target
forward pass, not the draft head, so a head swap was not expected to move the
192k decode rate either. The `n_max=3` / `--spec-draft-p-min 0.75` follow-up was
not run because no head qualified for it.
