# EXP-2026-09-09-052 — реализация L2-only: изолированные варианты CUDA Graph (VARIANTS=1/2)

- Status: `DONE` — A/B завершён, performance-кандидат `REJECTED` (implementation+model-free-gate
  2026-09-09: L2-only, default `GGML_CUDA_GRAPH_VARIANTS=1`, безмодельный гейт 32/32, память
  измерена; модельный A/B 8 пар = 4×A→B + 4×B→A по распоряжению Игоря от 2026-09-09 «запускай» +
  «4 раза AB и 4 раза BA», 16 серверных прогонов одним бинарником, все руки последовательно).
- Дерево: `work/llama.cpp-exp052-variants` (копия baseline exp046 + только изменения EXP-052);
  сборка: `build/exp052-variants` (Release, GGML_CUDA_GRAPHS=ON). L1 не трогать.
- Реализация (по решению EXP-051):
  - значение карты `cuda_graphs` — `ggml_cuda_graph_entry` (per-key: arch-flag, last_used,
    счётчики диагностик, `slots`), `common.cuh:1266-1278`;
  - слот = прежний `ggml_cuda_graph` (graph/instance/warmup_complete/uid/last_used/node_props),
    `common.cuh:1238-1263`; лимит слотов на ключ — env `GGML_CUDA_GRAPH_VARIANTS` (default 1,
    кламп 1..8), `ggml-cuda.cu:2930-2943`;
  - выбор слота: чистый скан memcmp-снапшотов (`ggml_cuda_graph_slot_matches`, ggml-cuda.cu:2946),
    затем новый слот при запасе, затем недогретый, затем LRU; совместимость — прежний побайтовый
    memcmp `node_properties` (весь ggml_tensor узла + src data/ne/nb), хэшей нет;
  - reset/capture/launch — по выбранному слоту; снимок соседа не перезаписывается; ExecUpdate-fail —
    destroy+re-instantiate только своего слота (seam `GGML_GRAPH_TEST_FAIL_UPDATE`);
  - sweep 10 с — по ключу; destroy — по слотам; `set_enabled`/`update_required`/`update_executable`
    переведены на slot-based API; `graph_compute`/`evaluate_and_capture` берут выбранный слот.
- Безмодельный гейт: `results/archive/EXP-2026-09-09-052/` (`exp052_gate.c`,
  `run-model-free-exp052.sh`, логи `gate-*.log/.out`, `SHA256SUMS.txt`). GPU-бэкенд живой,
  моделей нет. Итог: **32/32 PASS** (после двух правок harness по ходу, см. ниже).
- Сценарии и результаты (каждый — против контрольного пути `GGML_CUDA_DISABLE_GRAPHS=1`,
  контрольные суммы раундов совпадают во всех сценариях):
  - S1 alt (1->3->1->3 на одном ключе): VARIANTS=2 — оба слота доходят до launch, ровно 2
    capture, warmup reset после прогрева нет; VARIANTS=1 — ловушка EXP-050 точно воспроизведена
    (0 launch, цикл reset/unstable/capture).
  - S1b rebuild: ctx пересоздаётся на том же metadata-буфере — 1 capture, далее только launch
    (lifetime ключа/адресов через llama reset() подтверждён на синтетике).
  - S2 third (третья форма 7): LRU-вытеснение, >=3 capture, обе исходные формы возвращаются к
    launch на своих слотах; восстановление вытеснённого слота полное (reset -> capture -> launch —
    правка последовательности harness, первая версия обрывалась на capture).
  - S3 shift: смена указателей metadata при той же форме -> новый ключ, first_call+capture,
    launch на обоих ключах.
  - S4 failupd (seam ExecUpdate): маркер ровно 1 раз; после сбоя соседний слот продолжает
    launch, пересозданный слот сам доходит до launch (проверка по порядку строк в логе).
    Важно: переименование SRC-тензора snapshot не видит (в снапшоте только data/ne/nb src — семантика
    upstream node_properties); триггером сделан rename самотного узлового тензора (`node[0].name`).
  - S5 sweep: после 11 с простоя ключ сброшен (first_call заново), ре-конвергенция к launch,
    teardown чистый (exit 0).
  - OFF: без `GGML_GRAPH_DIAG` — ноль диагностических строк, контрольные суммы совпадают.
- Примечание по автомату: естественный (не seam) `event=exec_update_failed` сработал 2 раза в S2 —
  реальный отказ ExecUpdate при повторном capture другой формы в занятый слот; fallback
  destroy+re-instantiate отработал, контрольные суммы совпали с контролем.
- Фактическая память (измерено, не оценка):
  - host: `event=slot_struct bytes=96` + снимок 1056 B/узел (`event=sizeof_node_props`).
    Дополнительный слот VARIANTS=2 на ключ драфта: 96 + 116x1056 = 122 592 B; второй ключ:
    96 + 63x1056 = 66 624 B; итого доп. host для двух ключей драфта = 189 216 B (~185 KiB).
    Для target-сплитов — только если у ключа реально заведётся второй вариант ( upper bound на
    сплит: 96 + 1056 x n_nodes сплита ).
  - device: гейт `mem` (100 ключей, 4 вызова на ключ): занято графами ctl=2 097 152 B;
    VARIANTS=1 (100 instance) = 10 485 760 B; VARIANTS=2 (200 instance) = 20 971 520 B.
    Доп. instance+graph = 10 485 760/100 = ~104.9 KiB ( granularity cudaMemGetInfo 2 MiB ->
    диапазон на instance ~84-105 KiB для 1-узлового графа). Для драфта доп. 2 instance ~ 0.2 MiB
    VRAM на фоне 10.6 ГБ; стоимость instance для 63/116-узловых графов проверить в A/B
    (cudaMemGetInfo до/после + счётчик слотов).
- Итог: L2-only реализован, default VARIANTS=1 побайтово совместим со старым поведением (ловушка
  EXP-050 воспроизведена), VARIANTS=2 даёт сосуществование форм 1/3. Готов к предварительному
