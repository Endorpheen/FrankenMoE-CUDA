Goose port of the model-facing half of `src/llama-model-saver.cpp`:

- `savm_add_kv_from_model` — `add_kv_from_model` (147-449): the architecture
  and model name, the vocabulary tables, the hparams scalars and arrays, the

The native model constructor `llama_model_saver(const llama_model *)` only

accepted `sav_init` state constructor (S4) and `savm_supports_arch`.

## Why the model is synthetic

There are no model weights in this repository, so the gate builds a `TestModel`
(the seven pure virtuals stubbed, as in `EXP-2026-11-14-600-p6-09-lora-manifest`)
and fills exactly the fields the saver reads:

- hparams values installed directly on `hparams`;
- a **real** `llama_vocab` loaded by the real `llama_model_loader` from a tiny
  GGUF written by the fixture (tokens, scores, token types, merges, special
  ids); a vocab-less case uses `tokenizer.ggml.model = "no_vocab"`;
- empty `ggml_tensor`s with names, shapes and types; only descriptors are
  compared, tensor data belongs to the accepted S4 gate.

Both natives (the saver and the vocabulary loader) are the real library ones.
Nothing is reimplemented on the native side.

## Port ABI

The port never dereferences `llama_model`. The host passes flat tables:

```
hv     integer/bool hparams, one slot per field          (tests/slots.h: H_*)
hf     f32 hparams                                       (HF_*)
ha     integer arrays, stride AV = LLAMA_MAX_LAYERS      (HA_*)
haf    f32 arrays                                        (HAF_*)
attrs  token attrs, scores token scores                  (raw llama.h values)
ix     runtime counts, layer counts, arch id, enum ids
s_off  resolved string table: arch, name, rope names,
       tokenizer model/pre, labels, prec names, tokens,
       merges
k_off  resolved LLM_KV key names in slot order
```

`source/model-saver.goose` and `tests/slots.h` are both generated by
`tests/gen.py` from the native `add_kv_from_model` and `llama-hparams.h`, so the
emission order, key list and field types cannot drift apart. The generator
translates only the *shape* of each native call; the semantics (GGUF type,
per-layer reduction, attr switch, rope scale, aliasing) are in the Goose file.

Decisions kept in the port:

- `n_layer = n_layer_all - n_layer_nextn` for every per-layer array, with the
  all-equal collapse to one scalar and an array otherwise; whole arrays
  (`rope_sections`, `deepstack_mapping_arr`, `xielu_*`) never collapse;
- `std::vector<float>(begin, begin + n_layer_all)` (the swiglu clamps) is a
  full array, **not** per-layer;
- `rope_scaling_factor` is `0` for an exact `1.0f` train scale, else `1/scale`,
  in f32;
- `ggml_prec`: names first, then one bool per name, `GGML_PREC_Q8 -> 0`,
  everything else `1`;
- the deepseek4 branch: `arch == DEEPSEEK4 || hc_mult > 0` writes one ratio per
  layer (no collapse), otherwise the per-layer reduction applies;
- the PLE group is whole or absent: the layer list is built from the
  `is_ple_impl` flags, then ngram/head arrays;
- `llama_token_attr` is a bit flag; the port maps it to `llama_token_type` with
  the native switch and the UNDEFINED default; a vocab-less model writes a
  zero-filled token-type array (UNDEFINED);
- an empty `std::string` is not written at all (the native template returns
  before `gguf_set_val_str`), while `std::vector<std::string>` still writes an
  empty array (the dedicated overload has no early return). This asymmetry is
  reproduced and gated;
- a non-empty precompiled charmap reaches the native `char` overload, which is
  `GGML_ABORT`; the port refuses with `-1` and does not write that key.

## Gate

```
bash tests/build.sh
```

`build.sh` runs `tests/gen.py` output through `goose --standalone`, compiles it
with `gcc-13 -O1`, builds `tests/fixture.cpp` against `libllama` and
`libggml-base`, and runs the comparison. Each case compares:

- the canonical KV dump (key, type, array element type, count, bytes) in
  emission order;
- the tensor descriptor dump (name, type, offset, dims, `ne[0..3]`).

`supports_arch` is compared over every `llm_arch` value (163 ids).

Recorded result:

```
FG_S5 cases=33 checks=5714 failures=0
```

32 model cases (32 = 30 differential + 2 port-only) and the arch sweep. The
cases cover: minimal model, `tok_embd`/`output` aliasing both ways, no tensors,
nextn layers, per-layer collapse, `n_embd_out`, SWA on/off, prec Q8/F32/all-Q8,
deepseek4 by arch and by `hc_mult` (including the branch where only `hc_mult`
changes the answer), PLE on/off, all six attr classes with special ids and
flags, BPE merges, vocab-less model, looped-arch pointer aliasing, duplicate
rope tensor, all model-level slots, zero layers, both rope scales, classifier
labels and whole arrays, default hparams, F16/I32 descriptors, empty model name,
and the port-only charmap refusal.

## Mutations

```
python3 tests/mutate.py --half 1
python3 tests/mutate.py --half 2
```

Each mutation rewrites the port, rebuilds at `-O0`, and must make the gate
fail. Compile errors are `build-failed`, not `caught`.

```
MUTATIONS 6/6 caught   (half 1: value types, vocabulary path)
MUTATIONS 6/6 caught   (half 2: decisions, tensor enumeration)
```

## Limits (honest)

- The model is synthetic: hparams are values, the vocabulary is real but tiny,
  tensors carry no weights. This is not a saved-model byte gate; the report says
  so.
- `llama_model_saver` in the flint tree differs from `upstream/llama.cpp`, so
  the arch list and extra `LLM_KV` keys are the tree's, not upstream's.
- Key names, the arch name, the rope order/scaling names and the tokenizer
  strings are resolved by the host through native `LLM_KV`/name helpers, as in
  the accepted S4 gate. The port owns order, types and conditions.
- The precision map is `std::map<ggml_tensor*, ggml_prec>`: its iteration order
  is pointer order. The fixture passes the names in exactly the map's order.
- Branches that are natively unreachable are listed in `REPORT.md`; the most
  important are the char overload (abort), a duplicate non-rope tensor (abort),
  `output` non-null with a null `tok_embd` (null dereference), and a zero-layer
  model (`n_expert_used()` aborts).
